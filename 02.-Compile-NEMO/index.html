Compile NEMO

Complete 01. XIOS compilation first. NEMO links against the XIOS library built in that step. Run step 4 from Scripts/.

. ./4.make_nemo.sh
  • The script loads the same GNU, parallel HDF5, and parallel NetCDF modules used to build XIOS. It also loads Subversion to check out NEMO 4.0.4 into $NEMO.

Note

Shared-library paths can vary between HPC systems, therefore you may need to adjust the library settings when building and running NEMO on another system. For example, the following command is commented out in this script:

bash export LD_LIBRARY_PATH=$CRAY_LD_LIBRARY_PATH:$LD_LIBRARY_PATH

This command was required for this build on ARCHER2 but was unnecessary on Cirrus, where the loaded modules already configure the required shared-library paths.

  • The script copies arch-cirrus-gnu-mpich.fcm into the NEMO checkout. This file tells NEMO which compiler and libraries to use. The script fills in $XIOS_DIR so the build can find the XIOS headers and library from step 3.
  • It adds $CONFIG OCE to cfgs/work_cfgs.txt. This provides the configuration name and tells makenemo to include NEMO's ocean component (OCE).
  • It copies the CelticSea1.5 customised Fortran files into the configuration's MY_SRC/ directory. When a local file has the same name as a standard NEMO source file, the build uses the local version.
  • It copies cpp_co9-amm7.fcm to cpp_$CONFIG.fcm. This gives makenemo the compile-time options for this configuration. The key_mpp_mpi option lets NEMO run across multiple MPI processes, and key_iomput enables output through XIOS.
./makenemo -m $HPC_TARG -r $CONFIG -j 16

Check the executable

After compilation, 4.make_nemo.sh checks whether nemo.exe is executable and prints its location if the check passes.

test -x $CONFIG_DIR/BLD/bin/nemo.exe
echo "Executable is $CONFIG_DIR/BLD/bin/nemo.exe"

Continue with 03. Run the model to use the prepared 1993 inputs. To generate your own inputs, start with 04. NEMO tools compilation.
